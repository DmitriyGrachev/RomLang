# Adaptive core, release 1.3.0

Implemented `wordReview` as an append-only learning event. Validation accepts known words and exactly `recognition` or `recall`; recognition requires a Boolean self-rating, recall requires a curated item and an answer of at most 200 characters. An empty answer is accepted only with `assisted:true` for an explicit reveal. Client-supplied correctness, result, source, and version are replaced by the canonical grade and `courseVersion` at ingestion. The persisted adjudication is replayed without regrading by the reducer. Existing attempt IDs, results, XP, and lesson completion remain unchanged.

`Snapshot.wordAttempts[wordId]` holds `{wordId,mode,answer,correct,spelling,canonical,assisted,source,at}` history. `wordReviews[wordReviewKey(wordId,mode)]` holds `{due,streak,lastAt,attempts}`. Recognition (`self`) and curated recall (`checked`) have independent schedules. Failures are due immediately and reset streak; assisted successes reset streak and are due after one day; unaided due successes advance through 1/3/7/14/30 day stages. Early unaided successes retain the due date and stage; older imported attempts cannot rewind an existing schedule. Duplicate IDs are skipped and word reviews give no XP.

The A1.1 practice bank is cataloged through `practiceTopics`, `practiceExerciseMap`, `wordRecallMap`, `exerciseOwner`, and `moduleForExercise`. Bank exercises join `exerciseMap`/`catalog.exercises`, while `catalog.lessonExercises` remains the original core lists, so bank work cannot satisfy lesson completion. `courseVersion` is exported from one `version.ts` source through `data.ts`.

Verification: the new test file failed before implementation because `word-memory.ts` did not exist. After implementation, 24 focused tests pass across word memory, historical records, sync, and existing records; `tsc --noEmit` and `git diff --check` pass. Tests cover spoofed results, bad word/mode, diacritic canonicalization, early and assisted scheduling, duplicate IDs, independent directions, old history defaults, immutable checked replay, and mock transport reload/export/restore. Full release/browser verification belongs to Task 5.

Import caveat: `restore` revalidates untrusted exported events, including their grades, against the current authored answers; a server-persisted event replay retains its original grade. This matches the existing restore security contract and prevents a forged export from claiming checked correctness.
